# The verifier shares the rules, never the rows

`verify-stores.ts` exists to catch the generator, so it may not be built out of the generator. It reads the deployed stores and compares them against the Markdown by its own route, and the line is this: it shares the pure classification rules — `placementOf`, `parseContentFilename`, `localeMatchesTree` — and reads a manifest's front matter raw, but it never imports `contentRowFor`, `seriesRowsFor` or `projectRowFor`, and it never reads `seed.sql`. The rules say what a Document *is*; the row builders say what a Document *becomes*, and only the second half is what the verifier is there to doubt.

Until now it doubted both halves, by having a second implementation of everything — its own walk, its own Locale regular expression, its own reading of what a file is. That is not redundancy, it is divergence with a schedule: the copy drifted, and drifted in the one direction that matters. It dispatched on `attributes.type` — the front matter — which is precisely the defect ADR 0004 removed from the generators, alive in the module whose job is catching it. `type: 'project'` had no branch at all, so the `project` table, `series_slug`, `project_slug`, `series_section` and `container_order` were compared against nothing. A wrong prune of a Project passed the publication in silence.

## Considered Options

Three readings of "independent" were on the table, and the ADR is really the choice among them.

- **Independent of the walker.** The verifier keeps its own recursive read of `app/content` and its own classification. This is what it did. Rejected: a classification with two implementations has two chances to drift, and one of them has no test — which is the whole story above. ADR 0004 already says there is one rule for what a file is; a second copy is a violation of it whoever writes it.
- **Independent of nothing.** Consume the generator's output and only compare it against the stores. Rejected, and it is the option this ADR exists to make hard: a generator that silently dropped a Document would then produce a seed and a verification that agree with each other and with nothing else. The script would still pass, still print `ok`, and mean nothing.
- **Independent of the row builders.** Chosen. Share what is pure, tested and singular by decree of ADR 0004; keep a second, naive reading of everything the generator *decides*.

The manifest is the case that shows where the line falls. A Part's `container_order` is the position of its slug in the manifest's list — `series-sql.ts` computes it while validating the arc, reconciling the listing against the disk and refusing contradictions. The verifier derives the same number with an indexed `forEach` over the same array and nothing else. It is the identical fact read the ingenuous way, which is what a second opinion is; importing the function that produces it would be asking the accused to testify.

## Consequences

- **`attributes.type` is not read by the verifier, at all.** Not compared, not checked, not consulted — placement classifies. That the field disappears from the file is the visible proof that the ADR 0004 defect is closed; it is legible in the diff rather than argued in a comment.
- **A file that will not classify fails the run.** `placementOf` returning an error, or a filename carrying no recognised Locale under a tree that requires one, stops the verification instead of being skipped. The old leniency rested on "the build already caught this", which holds in `local` and not in `remote` — that mode measures the deployed store, and nothing guarantees the checkout is the one that seeded it. A Document that yields no expectation is indistinguishable from a correct one when what you compare is sets.
- **Leniency survives only for content states.** `draft: true`, and a `draft` that is not a boolean, are still skipped rather than re-litigated. Those are things a Document *says*; the two above are things it *is*.
- **The expectation moves to `seed/store-expectation.ts` and gets a test.** It takes `Array<{ relativePath, attributes }>` — plain data, the caller owns the disk — and returns the expectation plus the comparators. This is the split every other module in the pipeline already has and this one never did, which is where the defect hid. `verify-stores.ts` keeps `wrangler`, the filesystem, the report, and the whole KV half, which this does not touch.
- **Comparing values needs a comparator that names them.** Presence is a set difference; `container_order` is not. Widening the `content` key to carry the Container columns would report a wrong position as one missing item plus one unexpected item, two long strings to diff by eye. The attribute comparison is separate so it can say which column is wrong and what was expected.
- **An empty expectation is a failure for `content` and nothing else.** Comparing two sets bidirectionally makes empty-against-empty pass forever, so a broken derivation would certify an empty store. `generate-seed-sql.ts` already treats an empty walk as impossible and aborts; the verifier now agrees for `content`. `project`, `series` and `series_section` may legitimately be empty — the schema ships before the first one is written — so no floor is claimed there.
